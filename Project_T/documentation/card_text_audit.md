# Card text audit (2026-10-02)

User: *"check every card's text."* Every Dream card's text against what the game data and code
actually do. The full per-card table is `card_text_audit.csv` (335 cards: id · text · Needs · stacks
· data fields · rule constants · number check), generated by `tools/card_text_audit.gd` (Roguelite
Code). Tower Code's rule list is `tower_rule_hooks.md`. This file is the verdict.

## Method

1. **Numbers.** Every number in a card's text must match a data field or a code constant (with
   derived forms: 25% ↔ 0.25, 25% more ↔ ×1.25, 25% less ↔ ×0.75). The tool's first pass flagged 198
   cards. Most were false alarms: it only saw constants on the same code line as the rule id.
   Matching constants **by name** (`COZY_CORNERS_*`, `HERD_*`, `PULL_UNDER_*`…) and reading the
   remaining cards' code by hand left the real findings below.
2. **Mechanics.** For every card whose numbers live in code, the rule was read in the code
   (DreamState, DreamEffects, tower.gd, reactions.gd, kinships.gd, crowned_ground.gd).

## The test

`tests/test_card_text.gd` should:
- **match constants by name** as well as by rule-id line (rule id in capitals + `_`, plus the
  card's `extra_rules`), which turns ~198 flags into the real ones;
- **check unlock cards' prices** against `TowerData.evolve_cost` / `cost` (or, with the token, check
  that no unlock card has a hand-written price);
- keep KNOWN only for derived numbers it can't see (Soaked Through II moves off it once the strength
  bonus is understood: 20% × (1 + bonus)).
